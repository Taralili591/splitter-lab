# 员工手册 RAG 切块实验室

用同一份虚构员工手册，比较六种资料处理方式真正生成的文本块、排序和最终阅读材料，再选择是否让 DeepSeek 回答。

## 启动

在仓库根目录 `rag-chunking-lab` 中运行（首次使用先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)）：

```bash
uv run python -m labs.hr_chunking_lab --open
```

uv 会按仓库中的 `.python-version` 使用 Python 3.12 并准备依赖。浏览器地址为 `http://127.0.0.1:8768`。端口被占用时加 `--port 8769`。依赖准备好后，macOS 可以双击仓库根目录的 `启动实验室.command`，Windows 双击根目录的 `启动实验室.bat`。本实验只依赖 `requests`；Windows 另装 `tzdata`，不需要下载本地大模型或大型 RAG 框架。

不使用 uv 时，可按[根目录 README](../../README.md)用 Python 3.11+、虚拟环境和 `requirements.txt` 安装，再运行 `python -m labs.hr_chunking_lab --open`。

## 填写 API

在页面右上角的「连接与密钥」中填写并保存，或编辑本目录 `.env`。两个服务的密钥分开填写：

```dotenv
DEEPSEEK_API_KEY=填写你的DeepSeek密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash

SILICONFLOW_API_KEY=填写你的硅基流动密钥
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1
SILICONFLOW_EMBEDDING_MODEL=BAAI/bge-m3
```

模型名能在页面修改，接口地址可在 `.env` 修改。默认对话模型使用 DeepSeek 官方当前文档中的 `deepseek-flash`，请求关闭思考模式以便观察简短回答；不要继续使用已退役的 `deepseek-chat` 默认名。如果账户不可用当前默认模型，请填入该平台账户实际支持的模型 ID。

配置顺序为：非空进程环境变量、本实验 `.env`、项目根目录 `.env` 中原有的硅基流动配置。兼容旧的 `RAG_LAB_BASE_URL` 和 `RAG_LAB_EMBEDDING_MODEL`。根目录配置只读；在页面保存时只写本实验自己的 `.env`。留空的密钥输入框表示保留原值。页面不会回显已保存密钥。

## 第一轮建议这样玩

1. 打开「切块预览」，对照完整原文和选中资料块：不同块使用不同淡色，金色表示原文在多个块中重复出现。点击块编号可定位原文，上一块和下一块可核对接缝。切换固定、递归、结构、父子四种方式，观察同一条制度在哪里被拆开。预览这四种方式无需模型调用。
2. 选 Q01，先保留各方案默认切块参数，以及公共 Top K 与材料预算，点击「检索资料」。向量检索使用硅基流动真实 Embedding，不会自动调用回答模型。
3. 切到「六组对比」，先选固定和父子，比较命中小块、回填父块、实际交给 AI 的材料和未装入原因。之后再加入其他方案。
4. 在阅读区确认资料后，点击「让 DeepSeek 回答」。它只能看到本次实际装入预算的文本，不会收到整本手册或标准答案。
5. 展开「对照教材检查」，核对参考条款覆盖和标准答案。下载 JSON 记录可用于录屏、回看或自己判卷。

没有填写 API 时，可选择「BM25 关键词 · 离线」，先比较固定、递归、结构和父子。它是真正的本地关键词排序，明确区别于向量检索；不会用假向量冒充 Embedding。语义切块仍需要句子 Embedding；上下文补充仍需要 DeepSeek 生成背景。

## 直观看递归和文档结构的区别

打开「递归 vs 结构」，先选择短章节样例并保持块长上限 280。两章合计不足 280 字符，真实递归算法可以把它们合成一块；结构方式仍会在章节边界分成两块。原文与结果使用相同的章节颜色：绿色表示公司福利年假，橙色表示加班调休，卡片边框表示真正的资料块。一张卡内同时出现两种颜色，就能看出它包含两个章节。

点击任意资料块可定位原文。切到长章节样例，观察结构方式也会在过长章节内部继续递归细分，避免误以为“一章永远等于一块”。两组始终使用同一原文、同一长度上限、零重叠，页面只比较原文切口，不额外附加章节标题路径，不调用模型，也不消耗 API。原来的完整员工手册、题库和检索实验保持独立。

录屏可按以下顺序进行：

1. 指向短样例原文的两个章节：“这里一章讲年假，一章讲加班。”
2. 指向递归的一张混色卡：“两章加起来放得下，递归就可以把它们装在同一块。”
3. 指向结构的两张单色卡：“结构方式先分清章节，即使没装满，也把它们分开。”
4. 切到长样例：“章节太长时，结构方式仍然需要在章内细分。”

这一页证明的是章节边界如何约束切块，不预设哪种方式检索更准。完整检索实验中的结构方式还会附带章节标题参与检索，标题线索的作用应与切口区别分开解释。

## 参数放在哪里

左侧「公共检索设置」只放检索方式、Top K 和材料预算，所有方案共用。点击一种切法后，其下方「当前切法专用」只显示本方案有效的参数；数值在本次页面会话内分别保留，切换方案不会串用。

| 切块方式 | 本方案可调参数 |
| --- | --- |
| 固定长度加重叠 | 块长上限、重叠 |
| 递归切块 | 块长上限、重叠 |
| 文档结构切块 | 块长上限、重叠（章节内部） |
| 语义切块 | 长度尺度、语义分界百分位 |
| 上下文补充 | 原文块长上限、原文重叠 |
| 父子切块 | 子块上限、子块重叠、父块上限 |

「恢复公共默认」只恢复公共检索设置；「恢复本方案默认」只恢复当前切法。对比卡展示本轮实际使用的切块设置，点击「调整本方案」可返回对应编辑区。修改参数后，旧结果会提示需重新检索；其他方案的专用参数与已有记录不受影响。修改公共检索设置则会使各组旧检索结果过期。

首次对比可保持各方案默认值，之后每次只改一项，查看真实切口和检索材料的变化。批量构建、检索和 JSON 导出都会保留每个方案实际使用的参数。

## 六种实现

| 方式 | 切块和索引 | 搜索后交给 AI 的内容 | 首次构建所需服务 |
| --- | --- | --- | --- |
| 固定长度加重叠 | 按原文字符窗口切，边界固定 | 命中的原文块 | 向量模式需要硅基流动 |
| 递归切块 | 段落、换行、中文句界等逐级拆，重叠为最大目标 | 命中的原文块 | 向量模式需要硅基流动 |
| 文档结构 | 不跨 Markdown 章节，过长再拆，标题路径进入索引 | 原文块与真实章节标题 | 向量模式需要硅基流动 |
| 语义切块 | 对句子调用真实 Embedding，按相邻句距离的分位数分界，并限制长度 | 命中的原文块 | 硅基流动 |
| 上下文补充 | 与递归保持相同原块，DeepSeek 仅按整本手册补背景后一起索引 | 自动生成背景及原文；覆盖判断只算原文 | DeepSeek；向量模式另需硅基流动 |
| 父子方式 | 对小块建立索引并保留其父块关联 | 命中后回填的父块，按父块去重 | 向量模式需要硅基流动 |

语义分界百分位越高，一般切得越少；最小长度是软目标，最大长度为块长的两倍。父块先在章节内按父块上限分割，再在父块中切子块。完整实现见 `chunking.py`。

## 比较规则

- 长度单位是 **Python Unicode 字符，不是 token**。最终材料预算包含引用头、结构标题、生成背景和父块正文，不包含问题及系统提示词。模型实际返回的 token 用量另外保存在回答记录中。
- 所有方案共用检索方式、Top K 和材料预算，各用自身切块参数建库、排序并按排名装入；达到 Top K 或整块超出剩余预算就不装入该候选，不临时截断制度条款。相同父块去重；普通重叠块的重复文字仍占用实际阅读预算。
- 语义切块按模型输出决定边界；上下文背景是生成结果，可能有误，页面会保留它与原文的区别。两者首次构建会有真实 API 调用；过程记录显示进度。相同数据、参数和模型可复用本机缓存。
- 「参考条款整段覆盖」用原文字符区间合并计算。命中 `[F03]` 这个编号不等于拿到了 F03 的完整文字。该指标是保守检查，部分覆盖并不等于一定答错，也不是自动答题准确率。
- 原文颜色按真实字符区间绘制。金色重叠不按文字是否相同猜测；同一句话在不同位置出现不会被误标为重叠。递归切块以实际交集为准；父子方式另标出父块范围；DeepSeek 补充背景用独立紫色区域显示，不染进原文。六种循环淡色配合块编号使用，颜色重复不代表两块相同。
- 问题被修改后，不再继承原题的标准答案或个人事实。`quiz.json` 从不用于切块、补背景、Embedding 或回答提示词；只供操作者核对。每次回答是独立对话。
- 实验没有预设某种方法更好。不同方式可能给出相同正确答案，也可能因索引单位、边界、背景或阅读预算出现差异。先看真实资料，再解释结果。

## 文件

```text
data/handbook.md           唯一建库原文，可编辑后重新构建
data/quiz.json             12 题及标准答案，只有 10 题资料与事实齐全
data/assistant_prompt.txt  统一回答要求
data/boundary_demo_*.md    递归与结构的短、长章节对照样例
chunking.py               六种算法与精确原文范围
boundary_demo.py          同原文、同上限、零重叠的真实切口对照
visualization.py          原文颜色、真实重叠区间与父子范围
providers.py              两家 API、配置与向量缓存
engine.py                 构建、排序、预算装入、覆盖检查与回答
server.py                 本机 HTTP 页面与异步任务
web/index.html            实验页面
runtime/                  本机缓存与导出记录，已被 git 忽略
```

修改手册、模型、块长等设置会产生独立缓存。上下文和向量的缓存保存在 `runtime/`，答案每次显式生成，不自动复用旧回答。页面显示的「构建完成」只指本轮对应设置。
